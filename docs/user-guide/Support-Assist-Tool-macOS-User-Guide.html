Support Assist Tool v0.5.0 — macOS User Guide

Instructions for installing, operating, reviewing cases, collecting evidence, and using the Support Assist Tool on macOS. Procedures in this guide describe the macOS application.

Introduction

About this guide

This guide covers the macOS edition of Support Assist Tool 0.5.0. It describes controls and workflows implemented by the macOS application.

Introduction

What’s New in 0.4.x

This guide covers the 0.5.0 line. The behaviour changes made in 0.4.12 are listed in the Windows User Guide, which carries the full history.

This section summarizes the 0.4.x line for engineers upgrading from 0.3.x.

VersionChanges
0.4.0Introduced the case-centered workspace, active-case ownership for evidence, broader collection workflow, environment review foundations, and execution-host diagnostics.
0.4.1Expanded structured Log Review, machine and activity correlation, evidence selection, case notes, environment summaries, and persistence of review state.
0.4.2Moved parsed/review state into case-owned storage, strengthened tool lifecycle behavior, and established the cross-platform Core used by later Linux and macOS editions.
0.4.3Reorganized diagnostic tools into clearer categories, expanded Guided and Network diagnostics, improved case workflow, and added extensive usability and reliability corrections.
0.4.4Added the first-class Explorer workspace, SSH/SFTP and remote-workspace functions, richer Environment Review, Remote Console work, improved diagnostics, and Windows Explorer/remote-view refinements.
0.4.8Log review reports every Veeam component a bundle contains rather than a single product, and attributes runs to the component that performed them. Added collection and review coverage for the SAP HANA, SAP on Oracle, SAP MaxDB and IBM Db2 plug-ins, and expanded debug logging with timed operations and handled exceptions.
0.4.7Corrected remote file transfer against hosts that refuse the SFTP subsystem, reduced each remote operation to a single SSH session, and made log collection name and record its bundles predictably.
0.4.5Expands native Linux and macOS engineer workflows, adds platform capability reporting, self-contained portable packaging, optional POSIX ODBC loading, and platform-specific product documentation.
0.4.9Case Manager as the page case work starts from, with editable status, next steps and notes; Log Review cards that open what they summarise; machine, job and run selectors that narrow each other; a log viewer with line numbers, find, and severity colouring; deep scan of a single run; and appending new evidence to an existing case.
0.4.10A Case Questions block that answers the questions a case opens with, and a Service Activity section for problems that are not a failing job run. System error codes are translated where they appear. Backup type is read from the file the run wrote, so an incremental is no longer reported as a full, and scheduled runs are identified as scheduled. A bundle holding several machines names the machine it describes, a backup server bundle is no longer reported as an agent bundle, and the review reports how many archived logs it did not open.
0.4.13The Integrations page became a grouped card catalogue (Launch, Assisted, Database) that detects each tool where it is installed before offering to acquire it; an interactive database console for psql and SQLCMD with a guided query builder; guided runs; and licensed Engineer mode.
0.4.14The last 0.4.x line. Its changes are listed in the Windows User Guide, which carries the full history.

The AppKit edition has Active Case selection, case actions, Log Review, categorized Tools, independent network diagnostics, optional ODBC SQL, Filesystem Change, SSH/SFTP, Remote Console, macOS Host Diagnostics, Integrations, Diagnostics, Recent Activity, and self-contained application packaging.

Getting Started

Run the self-contained macOS application

The distributable macOS edition is intended to be delivered as SupportAssistTool.app with required non-Apple runtime libraries under Contents/Frameworks. Homebrew is not required to run the packaged SAT application.

Start SAT
  1. Copy/extract SupportAssistTool.app to an approved location.
  2. Ensure the application comes from your approved SAT distribution/signing process.
  3. Open the application normally in Finder or with open SupportAssistTool.app when using Terminal.
Expected result. The native AppKit window opens without requiring Homebrew packages for SAT-owned runtime libraries.

Application bundle

The distributed SupportAssistTool.app carries SAT-owned non-system runtime libraries inside the application bundle. Apple system frameworks remain provided by macOS. Run the organization-approved signed/notarized bundle from a trusted location.

No Homebrew runtime requirement. Homebrew is not required to run the packaged SAT application. Optional vendor integrations such as a database driver can still be required for the feature that uses them.
Getting Started

Workspace roles

The macOS application identifies the current role as Engineer Review or Customer / Lab Execution Host. Customer/Lab enables local execution-host diagnostics for the current session; Engineer Review is intended for case review and evidence work.

RoleUse
Engineer ReviewCase review, saved evidence, reports and remote/portable diagnostics that do not require local execution-host actions.
Customer / Lab Execution HostRun macOS host diagnostics and local zsh commands on the machine being tested. Enablement applies to the current SAT session.
Getting Started

Navigation

The macOS navigation includes Home, Case Dashboard, Environment Review, Health Monitor, Log Review, Explorer, Tools categories, Integrations, Diagnostics, Recent Activity, and Help / About.

The macOS application exposes Home, Case Dashboard, Environment Review, Health Monitor, Log Review, Explorer, categorized Tools, Integrations, Diagnostics, Recent Activity and Help / About. Use the persistent Active Case selector when changing case context.

Upgrade

Manual Upgrade from 0.3.x

Use a side-by-side manual upgrade. The macOS application does not provide a general 0.3.x workspace converter.

Preserve and move to 0.5.0
  1. Close the older SAT application.
  2. Copy the complete older SAT/case directories and source log bundles to protected storage.
  3. Install/copy the 0.5.0 application separately.
  4. If a workspace already contains case metadata accepted by 0.5.0, open Case Dashboard, enter the existing case root and choose Register Case.
  5. If the older workspace is not accepted, create a new 0.5.0 case and review the preserved original logs/bundles.
  6. Use Load Saved Review only for a compatible case that actually contains current-readable structured review state.
  7. Verify the case summary, Note Review, and PDF Master before retiring older files.
Expected result. The old data is retained until the engineer confirms the 0.5.0 case workflow.
Working with Cases

Active Case

The header Active Case selector switches among cases registered with the macOS application or No Case. Select the correct case before starting review/report actions that should belong to a case.

Switch the active case
  1. Open the Active Case selector.
  2. Choose the required registered case or No Case.
  3. Open Case Dashboard and confirm the displayed case before reviewing or generating case-owned output.
Working with Cases

Case Dashboard

The macOS Case Dashboard exposes case fields and the actions Create Case, Register Case, Use No Case, Load Saved Review, Note Review, PDF Master, and Delete Active.

Register a compatible existing case
  1. Open Case Dashboard.
  2. Enter the existing case root in the case location field.
  3. Choose Register Case.
  4. Confirm the case in Active Case and inspect the dashboard text.

Case actions available on macOS

ActionPurpose
Create CaseCreates a new case from the Case ID/parent information entered in the macOS case workflow.
Register CaseRegisters a compatible existing SAT case root.
Use No CaseClears the active case context without deleting a case.
Load Saved ReviewLoads compatible structured review data already stored with the case.
Note ReviewDisplays note material represented by the saved case review/evidence state.
PDF MasterGenerates the case master PDF.
Delete ActiveStarts guarded deletion for the selected recognized case.
Working with Cases

Saved review and Note Review

Load Saved Review loads an already persisted structured review for the active case. Note Review displays the note material represented by the saved case review/evidence state.

Feature availability. The macOS edition does not provide the Windows row-level Add/Remove from #note actions. Review existing note material through Note Review.
Load saved review data
  1. Select the Active Case.
  2. Choose Load Saved Review from Case Dashboard.
  3. Review the summary represented by the saved structured model.
  4. Choose Note Review for stored note material.
Feature availability. The macOS edition does not provide the Windows row-level Add/Remove from #note actions. Do not follow the Windows row-selection procedure on macOS.
Working with Cases

PDF Master

PDF Master creates the case master PDF report through the shared report engine. Review the report before sharing customer evidence.

Generate PDF Master
  1. Select and review the required case.
  2. Choose PDF Master.
  3. Review the generated report before sharing it with the case record or another recipient.
Review

Log Review

The macOS Log Review page contains a source field, optional case-root field, Full Review, Browse..., Detect Local, and Review Source.

Review logs
  1. Open Log Review.
  2. Choose Browse to select a ZIP/directory/log file, or use Detect Local on a Customer/Lab host.
  3. Use the active case by leaving the optional case field appropriate to the current context, or provide the supported case root.
  4. Select Full Review before starting when complete analysis is required; otherwise use the faster preliminary path.
  5. Choose Review Source.
Expected result. The page displays the generated review summary/results. The macOS edition presents the review summary without the Windows machine/job/run selector set.

Review modes

Select Full Review before starting when complete analysis is required; leave it clear for the faster preliminary/index workflow. The macOS result page does not provide the Windows machine/job/run selector set, so use the macOS summary/results and Case Dashboard actions described in this guide.

Case context

Use a supported case root/current Active Case when the review should become case-owned. A raw source can also be reviewed for investigation without creating a case first, subject to the workflow shown by the page.

Review

Environment Review

Choose Refresh Environment to collect macOS-native environment/product context. The page uses detected Veeam products and shared environment data with macOS-native collection underneath.

Refresh Environment Review
  1. Open Environment Review.
  2. Choose Refresh Environment.
  3. Review macOS-native operating-system, product, storage/network and related environment context returned by the collector.

This workspace gathers diagnostic context; it does not automatically change host configuration.

Review

Health Monitor

Choose Refresh Health to collect CPU, memory/swap, filesystem, network, and top-process observations through the shared health model and macOS-native telemetry.

Refresh Health Monitor
  1. Open Health Monitor.
  2. Choose Refresh Health.
  3. Review CPU, memory/swap, filesystem, network and top-process observations.
  4. Correlate health findings with the case/log evidence before drawing a conclusion.
Review

Recent Activity

Recent Activity displays bounded activity records for the macOS SAT installation. Sensitive console command text and credentials are not intended to be recorded as activity details.

Recent Activity is a bounded record of SAT operations, completions, failures and cancellations. It is not a shell history. Local/SSH console command text and credentials are deliberately excluded.

Explorer

Local

The Local Explorer workspace browses local approved paths and can mark/unmark approved files for Universal Log Collection. The Local workspace uses the macOS file-browsing controls provided by this edition.

Local file workflow

Use the Local tab for approved local paths and for marking/unmarking approved files for Universal Log Collection. The macOS edition uses native path/list controls rather than the Windows Details file pane. Marking an item prepares it for collection; it does not transfer the item by itself.

Explorer

SSH / SFTP

The macOS SSH/SFTP workspace provides host, port, user, session-only password, remote path, host-key probing, Connect/List, Upload, and Download controls.

Connect and list
  1. Enter host, port, user, and session-only authentication information.
  2. Choose Probe Key and independently verify the SHA-256 fingerprint.
  3. Trust the verified key for the current SAT session.
  4. Choose Connect/List for the remote path.
Expected result. The remote listing/result is shown in the workspace.
Transfer
  1. Enter/select the approved local path and remote path required by the transfer.
  2. Choose Upload → to send the local file, or ← Download to retrieve the remote file.
Expected result. SAT reports completion/failure. The macOS workspace uses local and remote path fields with remote listing output for transfers.

Host-key trust

Choose Probe Key before authentication, verify the displayed SHA-256 fingerprint through an independent trusted source, and trust the verified key only for the current SAT session. A mismatch must be investigated rather than ignored.

Transfer workflow

The macOS edition uses local/remote path fields and remote listing output. After Connect/List, choose the required local/remote path and use Upload or Download. Credentials/passphrases remain session-only.

Explorer

Remote Console

Remote Console supports Local host (zsh) in Customer/Lab mode and adds a host (SSH) target after a successful SSH/SFTP connection. Enter the command and choose Run Command.

Local command execution is not exposed as an automatic privileged/root shell.

Run a local zsh command
  1. Use Customer / Lab when SAT is running on the Mac being diagnosed.
  2. Open Remote Console and select Local host (zsh).
  3. Enter and run the command.
  4. Review the returned output/status. SAT does not automatically elevate the command to root.
Run an SSH command
  1. Establish a trusted SSH/SFTP session.
  2. Select the host (SSH) target.
  3. Run the command with the permissions of the authenticated SSH account.
Explorer

Windows Remote status

The Windows Remote tab is not available. Use SSH/SFTP where the target supports SSH.

Tools

Tools catalog

Choose a category in the macOS Tools catalog and use Open Selected Category. Categories are Log Collection, Guided Diagnostics, Network Tools, SQL Tools, Filesystem Change, and macOS Host Diagnostics. Non-applicable Windows technologies show an explanatory state.

Select the category and choose Open Selected Category. macOS keeps the same recognizable category organization for everything it can actually run. Windows-only technologies do not appear as categories at all; see Windows-only technologies for what they are and what to use instead. A category that could never execute would only teach you to click something that does nothingprocedure.

Tools

Log Collection

Universal Log Collection detects Veeam products, checks detected products by default, and allows the engineer to control the product checklist. Unchecked products are not silently re-added. Collection is bounded to approved support evidence.

Create a macOS log collection
  1. Open Log Collection.
  2. Review detected Veeam products and selected product sources.
  3. Clear sources you do not want included.
  4. Include any approved local items explicitly marked from Explorer when required.
  5. Start the collection and review the completed bundle before transfer.
Tools

Guided Diagnostics

Guided Diagnostics lists product-specific diagnostics applicable to the Veeam roles detected on the Mac, including description and KB/reference information. When no supported diagnostic applies, the page reports that state instead of running a Windows-only test.

Use Guided Diagnostics
  1. Open Guided Diagnostics.
  2. Review the task-named diagnostics that apply to detected Veeam roles on the Mac.
  3. Select the diagnostic and review its description/reference information.
  4. Run it and review the result. Windows-only diagnostics are not presented as successful macOS tests.
Tools

Network Tools

The macOS network-operation selector contains:

OperationPurpose
Network InterfacesReview interfaces used by the portable diagnostics.
TCP Connectivity TestTest target TCP connectivity.
TCP ListenerRun the controlled SAT TCP listener.
UDP Connectivity TestTest with SAT-aware UDP acknowledgement semantics.
UDP ListenerRun the controlled SAT UDP listener.
TLS Handshake TestInspect handshake/certificate information.

Connectivity/listener use

Select the operation first, then enter the address/port values required by that operation. TCP and UDP listeners provide a controlled cooperating endpoint for SAT connectivity tests. UDP without a cooperating acknowledgement cannot prove end-to-end success.

TLS Handshake Test

Use the TLS operation to inspect negotiated protocol/cipher and peer certificate/fingerprint information available from the connection. Compare the observed result with the Veeam workflow requirement being investigated.

Throughput Client/Server

Run the SAT throughput server on the cooperating endpoint and the client on the test endpoint. Treat the result as evidence for that tested path rather than a general network benchmark.

Tools

SQL Tools

The macOS SQL page can generate a permission script without connecting or run the permission diagnostic through native ODBC when a compatible ODBC runtime and driver are available. SQLCMD may remain an optional fallback. Credentials and connection strings are session-only.

Use SQL Tools
  1. Open SQL Tools and enter the server/database/principal information needed for the task.
  2. Choose Generate Permission Script when you want a script for review without connecting.
  3. Choose Run Permission Diagnostic when a compatible ODBC manager and database driver are available.
  4. Review the result. Missing ODBC/driver capability affects SQL Tools only; it does not prevent SAT from starting.
Tools

Filesystem Change

Filesystem Change exposes Root, Output, Baseline, Other snapshot, SHA-256, Capture Baseline, and Compare Snapshots. Windows-specific streams/file-ID/cloud-hydration controls are not exposed.

Capture and compare filesystem state
  1. Enter Root and Output locations.
  2. Select SHA-256 only when content hashing is required.
  3. Choose Capture Baseline.
  4. After the change/test window, select the comparison snapshot and choose Compare Snapshots.
  5. Review the reported differences.
Tools

macOS Host Diagnostics

Choose Refresh Host Diagnostics for read-only OS/kernel, hardware, storage, network/routes, TLS/OpenSSL, and detected Veeam product context.

Refresh macOS Host Diagnostics
  1. Open macOS Host Diagnostics.
  2. Choose Refresh Host Diagnostics.
  3. Review OS/kernel, hardware, storage, network/routes, TLS/OpenSSL and detected Veeam product context.
Tools

Windows-only technologies

These are Windows technologies with no equivalent on macOS. They are not presented as tool categories in the macOS edition, because a category that can never run is not a category. They are listed here so you know what they were and what to reach for instead.

  • VSS Tools — Microsoft VSS does not apply on macOS.
  • Registry Tools — the Windows Registry does not exist on macOS; use Filesystem Change/macOS Host Diagnostics for plist, launchd, and application configuration evidence.
  • WMI Diagnostics — WMI is Windows-specific.
  • VBR Diagnostics — a local VBR server role is Windows-based; macOS can still review VBR evidence and use portable remote/network diagnostics.
Tools

Integrations

Choose Refresh Integrations to inspect optional integrations recognized by the macOS build. The macOS page reports recognized integration availability. Windows-only acquire/remove procedures do not apply to the macOS edition.

The macOS page reports recognized optional integrations and their availability. It does not expose the Windows acquire/remove management workflow. Install or manage third-party software only through the method approved for the Mac/environment.

Reference

Diagnostics

Choose Refresh Self-Test on Diagnostics to refresh the macOS SAT self-test/build/platform state used when troubleshooting the application.

Refresh SAT self-test information
  1. Open Diagnostics.
  2. Choose Refresh Self-Test.
  3. Use the displayed build/platform/state information when troubleshooting or reporting a macOS SAT issue.
Reference

Security and sensitive data

  • Run the signed/approved SAT application bundle from a trusted location.
  • Verify SSH host-key fingerprints before session trust.
  • Treat passwords, SQL connection strings, console commands, logs, and generated reports as sensitive.
  • Customer/Lab enables local execution only for the current execution-host session.
  • Review evidence before sharing it outside the case workflow.
Reference

Troubleshooting

  • If the application is blocked by macOS security controls, verify that the bundle is the approved signed/notarized organization build; do not bypass policy without authorization.
  • If ODBC is absent, the rest of SAT continues to operate; SQL diagnostics report the missing capability when used.
  • If SSH/SFTP will not authenticate, complete host-key probe/trust first.
  • If an older case cannot be registered, preserve it and review its source logs in a new 0.5.0 case.

Case cannot be registered

Use Register Case only with a compatible 0.5.0 case root. Preserve older unsupported data and re-review the original log bundles in a new 0.5.0 case rather than modifying metadata to force registration.

Application is blocked by macOS

Verify the package is the organization-approved signed/notarized build. Do not disable Gatekeeper or other organization security controls as a troubleshooting shortcut.

SSH/SFTP authentication fails

Complete host-key probe/trust first. If the fingerprint differs from the expected host identity, stop the session and verify the endpoint.

Help / About

The macOS Help / About page displays build and deployment information. It is a native single information page, not the Windows multi-topic Help selector.
